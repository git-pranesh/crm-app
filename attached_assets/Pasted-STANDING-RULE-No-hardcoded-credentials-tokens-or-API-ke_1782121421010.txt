PART 1 — SETTINGS PAGE (client/src/pages/Settings.tsx)

Route: /settings. Already registered in nav under WORKSPACE.
Access: BRANCH_HEAD only — redirect other roles to /dashboard 
with a toast "You don't have access to Settings."

Page header: "Settings" (title) + "SLA rules, offers & message 
templates" (subtitle)

### Section A — SLA Rules (left card, matches mockup):
Card title: "SLA rules" with clock icon
Subtitle: "Response-time thresholds (IST). The clock pauses 
while a lead is On Hold."

4 rows, one per rule. Each row:
  Label (left): human-readable rule description
  Input (center): number input, current thresholdHours value, 
    editable inline — no edit mode toggle needed, just a number 
    input with the stored value pre-filled
  Unit label: "hours" (static)
  Save button: "💾 Save" — on click, PATCH 
    /api/admin/sla-config/:rule { thresholdHours: inputValue }
    Show inline success tick on save, revert to save button after 
    2 seconds. Show inline error if PATCH fails.

Row labels → rule key mapping:
  "First contact within Nh of creation" → FIRST_CONTACT_24H
  "Reach MQL within N hours" → LEAD_TO_MQL_5D
  "DQL meeting scheduled within N hours of MQL" → MQL_TO_DQL_5D
  "PP meeting scheduled within N hours of Proposal Ready" → 
    PROPOSAL_TO_PP_2D

Fetch current values on mount from GET /api/admin/sla-config. 
Pre-fill all 4 inputs. No page reload on save — update local 
state only.

### Section B — Offers & Schemes (right card, matches mockup):
Card title: "Offers & schemes" with gift icon
Subtitle: "Seasonal offers that can be tagged on a lead or quote."

Display existing active + inactive offers as pills:
  Active offer: orange/terracotta pill with offer name + 
    small toggle (on = colored, off = grey)
  Toggle click → PATCH /api/offers/:id/toggle { isActive: !current }
  Pill updates optimistically

Add new offer input (bottom of card):
  Text input placeholder "e.g. Summer Special"
  "+ Add" button → POST /api/offers { name: inputValue, 
    isActive: true }
  On success: new pill appears, input clears
  Input validation: block empty name

Do NOT show a delete button per offer — soft-toggle is the intended 
control. DELETE endpoint exists for edge cases but not in this UI.

### Section C — WhatsApp Templates (full-width card below A+B):
Card title: "WhatsApp templates" with WhatsApp icon
Subtitle: "Pre-approved message templates used across the automation 
flows. Read-only here."

List all 6 templates from GET /api/admin/whatsapp-templates:
  Each template:
    Label (bold): template label (e.g. "Pre-call intro", 
      "RNR follow-up", "Meeting confirmation", "MOM summary", 
      "Onboarding welcome", "On-hold notification")
    Body (below label): template body text, light grey background 
      textarea-style box, NOT editable (readonly)

No edit, no save — read-only per founder's mockup ("read-only here").
No PATCH endpoint exists for this — confirm PATCH returns 404 
as expected. Do not add an edit UI.

Route: /calendar. Add to nav under SALES section, between

natural in the grouped sidebar):
  SALES
    Pipeline
    Leads
    Meetings
    Calendar   ← new
    WhatsApp
    Discounts

Access: all roles. Each role sees their own scope (enforced 
server-side by GET /api/calendar?scope=mine|team).

### View modes: Month | Week | Day
Tabs or toggle at top right of page.

Do NOT use an external calendar library unless one is already 
installed. Check package.json first:
  - If react-big-calendar, fullcalendar, or similar already 
    exists → use it
  - If not → build a minimal custom calendar grid:
      Month view: 7-column grid, 5-6 rows, each cell = a date
      Week view: 7 columns (Mon–Sun), time rows (8am–8pm)
      Day view: single-column, time rows (8am–8pm)
    Simple is fine — function over flourish here. The important 
    part is meeting entries render correctly.

### Meeting entries on calendar:
Each meeting = a colored chip/block on its date:
  Color by type: DQL = blue, PP = orange, Onboarding = green
  Label: client name (truncated if needed) + time
  Click → navigate to /leads/:leadId (link to the lead, 
    do not open a separate meeting modal — lead detail has 
    the full meeting flow)

### Data fetching:
GET /api/calendar?from=<month-start>&to=<month-end>&scope=mine
Refetch when user navigates month/week/day (pass new from/to).

For BL/BRANCH_HEAD: show a "Scope" toggle — "My schedule" 
vs "Team schedule" — which switches between scope=mine and 
scope=team query param. DESIGNER and CRE do not see this 
toggle (scope=mine always).

### Empty state:
If no meetings in selected period: "No meetings scheduled 
for this period" centered in the calendar grid. Do not 
show a blank grid — it looks broken.

### Scheduling from calendar:
Do NOT build a "create meeting from calendar" flow — 
meetings are always scheduled from within a lead's detail 
page. On the calendar page, clicking a date does nothing 
(or a subtle tooltip "Schedule meetings from a lead's page").
