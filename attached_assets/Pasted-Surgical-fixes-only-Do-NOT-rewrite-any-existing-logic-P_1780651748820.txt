FIX G5 — CRE→BL round-robin logic
File: server/src/services/assignmentService.ts

Currently: no logic for which BL receives a lead when CRE escalates.

Add function selectBLForLead(excludeBLIds?: string[]):

async function selectBLForLead() {
  const bls = await prisma.user.findMany({
    where: { role: 'BL', isActive: true },
    orderBy: { totalLeadsAssigned: 'asc' }
  })
  if (!bls.length) return null
  return bls[0]  // fewest assigned = next in rotation
}

In PATCH /:id/stage handler (leads.ts) — when CRE moves 
lead to MQL and no assignedBLId is set:

if (newStage === 'MQL' && !lead.assignedBLId) {
  const bl = await selectBLForLead()
  if (bl) {
    await prisma.lead.update({ 
      data: { assignedBLId: bl.id },
      where: { id: lead.id }
    })
    await prisma.user.update({
      data: { totalLeadsAssigned: { increment: 1 } },
      where: { id: bl.id }
    })
    await createNotification(bl.id, 'New lead assigned', lead.id)
    await logActivity(lead.id, req.user.id, 'BL_ASSIGNED', { blId: bl.id })
  }
}

Export selectBLForLead from assignmentService.ts so it can be
